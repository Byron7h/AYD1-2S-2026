# Requerimientos: Guia general de ejemplos

Esta carpeta resume y explica el contenido de los archivos de Requerimientos del proyecto.

## Que es un requerimiento

Un requerimiento es una condicion, capacidad o criterio que el sistema debe cumplir para satisfacer una necesidad del usuario, del negocio o del entorno tecnico.

## Desglose principal de requerimientos

### Requerimientos funcionales (RF)

Que describen:

- Que debe hacer el sistema.
- Que acciones ejecuta ante eventos del usuario o del negocio.
- Que comportamiento observable se valida en pruebas funcionales.

Enlace de referencia:

- Requerimientos funcionales del ejemplo: [RFs-requerimientos-funcionales](RFs-requerimientos-funcionales)

### Requerimientos no funcionales (RNF)

Se dividen en:
- Requerimientos de restricción
- Requerimientos de calidad

#### RNF de restriccion (RR)

Que abarcan:

- Restricciones tecnologicas.
- Restricciones normativas.
- Restricciones operativas.
- Restricciones de interfaz.
- Restricciones de presupuesto.

Enlace de referencia:

- Requerimientos de restriccion del ejemplo: [RRs-requerimientos-restriccion](RRs-requerimientos-restriccion)

#### RNF de calidad (EAC)

Que abarcan:

- Escenarios de atributos de calidad redactados de forma medible.
- Estimulo, entorno, artefacto, respuesta y medida de la respuesta.
- Criterios verificables para validar rendimiento, confiabilidad, usabilidad y otros atributos.

Enlace de referencia:

- Requerimientos de calidad del ejemplo: [EACs-requerimientos-calidad](EACs-requerimientos-calidad)

## Como usar esta carpeta en clase

- Leer primero esta guia para ubicar el tipo de requerimiento.
- Revisar luego cada archivo de Requerimientos como ejemplo aplicado.
- Comparar la redaccion de RF, RR y EAC para evitar mezclar conceptos.
- Utilizar las plantillas incluidas en cada archivo como base para nuevos ejercicios.
